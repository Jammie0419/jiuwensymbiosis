# excavate —— 挖掘循环

目标：把土从一处搬到另一处。所有坐标都是**基座系三维点，单位米**（REP-103：
+X 机身正前方，+Y 机身左侧，−Y 机身右侧）——来自 `get_terrain` 的料堆字段
`x_m` / `y_m` / `z_m`，不要自己估算坐标。`dig_z_m` 是铲尖入土高度（通常取料堆
表面 `z_m`）；`dump_z_m` 是卸料时铲尖高度，**不是地面高度**——卸点太低时铲斗
张不开，土倒不出来。

## 工作流

1. **读地形**：调用 `get_terrain`，得到料堆清单（名称 / 坐标 / 体积）。根据任务话术
   （"左边的土堆""白色桩标旁"）选出挖掘堆和倾倒点；若任务直接给了坐标则跳过此步。
2. **站点与就位（可选）**：挖点/卸点都必须落在当前可达半径内。**移动的单位是
   机身中心（站点）**：站点 = 目标点沿其方位向回拉到包络半径处（挖 ~4.5 m、
   卸 ~5 m）。移动 = 先 `rotate_base` 把整车转到"当前位置→站点"连线方向
   （**头朝前**，θ=atan2(站点y, 站点x)，正=左转），再 `navigate_relative` 前进到
   站点。到站后目标点 ≈ 正前方 (新半径, ~0, z)；方位由上车回转自动对准，
   **不要用 rotate_base 去对准目标方位**——那是行走用的。
3. **逐斗挖掘（默认复合）**：一个站位能同时覆盖挖点和卸点时，对每一斗调用
   `dig(dig_x_m, dig_y_m, dig_z_m, dump_x_m, dump_y_m, dump_z_m)`——一个调用就是
   一次完整循环（对准→下铲→收斗→摆转→卸料）。斗数按任务话术（"挖两斗""装满
   为止"）；若 `dig` 返回 `ok: false`，读 `error` 字段：超出可达半径 / 卸点张不
   开斗 → 回到第 2 步走底盘或换卸点；铲斗未卸料 → 先 `home` 再继续。
4. **挖/卸需要不同站位时（拆分动作）**：卸点超出当前可达半径、或挖完后必须挪机
   才能卸（带载行走）时，改用拆分三步：
   `dig_soil(dig_x_m, dig_y_m, dig_z_m)`（挖满一斗，结束于 carry 姿态、
   payload.held）→ `rotate_base` + `navigate_relative` 把整机开到卸料站点
   （**带载行走**，按限幅拆条）→ `dump_soil(dump_x_m, dump_y_m, dump_z_m)`
   （卸料并收斗，payload.clear）。行驶后目标点坐标按"原坐标 − 已行驶向量"
   换算（见下方算例）。
5. **复查地形**：每挖完一斗（或拿不准时）再调一次 `get_terrain`——挖掘会改变
   地形，之前的坐标观察已失效；据此决定继续挖、换堆、还是收工。
6. **收工**：全部完成后调用 `home` 回到安全收拢姿态。**不管挖了几斗，序列最后
   一步都必须是 `home`**；只挖一斗也要 `home`，否则机械臂停在 dump 位形上。

## 注意

- **位置失效**：挖掘和行走都会让旧的料堆观察作废，凡是用旧坐标前先重新 `get_terrain`。
- **移动算例**：卸点要求在机身坐标 (0, 10)（左 10 m），超出 6 m 包络 ⇒ 站点 =
  (0, 5)（沿方位回拉到 5 m）；`rotate_base(+1.5708 rad)`（90°，拆 3 条 ≤0.7）→
  `navigate_relative(+1.0) ×5` ⇒ 到站后卸点 ≈ 正前方 (5, 0, 3.5) →
  `dump_soil(dump_x_m=5, dump_y_m=0, dump_z_m=3.5)`。rotate 的正负号：目标在
  机身左侧 ⇒ 正（左转），右侧 ⇒ 负。
- **挖点不能太近**：`dig`/`dig_soil` 会从挖点向机身方向拖 `cut_length_m`
  （默认 1 m），拖切终点半径必须 ≥ `dig_min_drag_radius_m`（215F 默认 3 m），
  也就是挖点半径至少 4 m。`get_terrain` 给的堆顶如果只有 3 m 左右，先把整机
  后退到堆顶半径 ≥ 4 m，再重新 `get_terrain`；不要把近处堆顶直接当挖点。
- **卸点要"够得着 + 有空间外翻"**：卸点以基座为原点，半径落在可达环带内，同时
  高度/距离要让铲斗能带着料到达，并在那里往外翻。太低太近的点（例如 (3,0,0)）在
  收斗状态下手臂就到不了，`dig` 会报 "cannot be reached while carrying the bucket
  closed"。自然卸点大约在半径 4.5–5.5 m、z 3–4 m。**基座系 +Y 是机身左侧**——
  任务要求倒到哪一侧，卸点的 y 就取哪一侧的符号：右侧如 (5,-1,3.5)，左侧如
  (4.5,2.5,3.5)（挖点 (5,2,1.95) 时）。不给 `dump_z_m` 时默认取该点地形高度
  + 3 m；显式给了就按给的值精确执行。
- **不要用"挖点 x − 3"这种向机身内侧推的算法**：半径会变得过小（例如
  `4.36 → 1.36`），高 z 时收斗 IK 根本够不到。卸点半径保持 4.5–5.5 m，用
  侧向/斜向偏移；例如挖点 `(4.36, 1.36)` 时，右侧卸点用 `(5, -1, 3.5)`、
  左侧卸点用 `(4, 2, 3.5)`（基座系 +Y 是机身左侧），不要用
  `(1.36, 1.36, 4.25)`。同方向向外推也要注意不要超过 `reach_max`。
- 本技能的机器没有夹爪，`payload.held` 表示**铲斗里有料**：`dig`/`dig_soil`
  的前置条件是斗空，`dump_soil` 的前置条件是斗满——`dig_soil` 结束后斗是满的，
  接着必须 `dump_soil`（或先带载行走到卸料站点），不要在斗满时调 `dig`。
- [motion.base] 底盘**每条命令**都有上限（数值见【当前状态】里的"工作范围"：平移一条、
  转动一条）。超出就必须拆成多条 `navigate_relative` / `rotate_base` ——「转一圈」要拆成
  多条（例如每次 1 rad 左右），一次发 2π 会被安全护栏拒绝、整条序列直接失败。
