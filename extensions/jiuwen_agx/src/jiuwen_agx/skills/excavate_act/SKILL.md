# excavate_act —— 学习策略挖掘循环

目标与 `excavate`（dig 版）完全一致：把土从一处搬到另一处。所有坐标都是
**基座系地面点，单位米**（REP-103）——来自 `get_terrain` 的料堆字段
`x_m` / `y_m`，不要自己估算坐标。

## 何时用 act_exec、何时用 dig

- 目标点/料堆位置常规、任务话语与以往相似 → `dig`（脚本循环，行为可预期、经过充分验证）。
- 目标点偏斜、料形不规则、或明确要求"用学习到的策略/ACT 模型" → `act_exec`。
- 两者参数完全同名同义，可以逐斗混用（这一斗 dig、下一斗 act_exec 不冲突）。

## 工作流

1. **读地形**：调用 `get_terrain`，得到料堆清单（名称 / 坐标 / 体积）。根据任务话术
   （"左边的土堆""白色桩标旁"）选出挖掘堆和倾倒点；若任务直接给了坐标则跳过此步。
2. **就位（可选）**：挖掘/倾倒点必须在当前可达半径内。若任务给的点离机身太远，
   先用 `navigate_relative`（或 `rotate_base`）把底盘挪到合理位置再开工。
3. **逐斗挖掘**：对每一斗调用
   `act_exec(dig_x_m, dig_y_m, dump_x_m, dump_y_m)`——策略自行走出
   对准→下铲→收斗→摆转→卸料的整段轨迹，直到铲斗装上又卸下才算一斗完成。
   斗数按任务话术（"挖两斗""装满为止"）。
4. **失败处理**：若 `act_exec` 返回 `ok: false`，读 `error` 字段：
   超出可达半径 → 回到第 2 步走底盘；铲斗有料未卸 → 先 `home` 再继续；
   策略输出被拒/拍数超限 → 换用 `dig` 完成这一斗（脚本循环总是可用）。
5. **复查地形**：每挖完一斗（或拿不准时）再调一次 `get_terrain`——挖掘会改变
   地形，之前的坐标观察已失效；据此决定继续挖、换堆、还是收工。
6. **收工**：全部完成后调用 `home` 回到安全收拢姿态。

## 注意

- **位置失效**：挖掘和行走都会让旧的料堆观察作废，凡是用旧坐标前先重新 `get_terrain`。
- **倾倒点要选在可达半径内**：离挖点几米内即可（不要选几十米外）；任务说"倒到某方向"
  而没给距离时，取距挖点 2~4 米的同方向点。
- 本技能的机器没有夹爪，`payload.held` 表示**铲斗里有料**；`act_exec` 的前置条件是斗空。
- 策略输出也会被关节限位校验：`error` 里出现 "policy output rejected" 说明模型给出了
  越限目标，直接换 `dig`，不要重试同一坐标。
- [motion.base] 底盘**每条命令**都有上限（数值见【当前状态】里的"工作范围"：平移一条、
  转动一条）。超出就必须拆成多条 `navigate_relative` / `rotate_base` ——「转一圈」要拆成
  多条（例如每次 1 rad 左右），一次发 2π 会被安全护栏拒绝、整条序列直接失败。
